## 适用范围

本指南用于把已经确认的 15 秒旁白片段转化为 Seedance 2.0 动画解说视频 Prompt。目标是让参考素材职责、旁白、画面动作和镜头推进彼此清楚，同时保持各片段的音色与画风一致。

提示词方法以 `official-seedance-2.0-prompt-guide.md` 为官方参考，以 `community-directing-notes.md` 为导演实践补充；模型参数、输入模式和素材上限始终以 LibTV 实时 schema 为准。

## 写作前准备

开始写 Prompt 前，先确认以下输入：

1. 当前片段最终旁白，以及实际朗读汉字数。
2. 按[音色参考与音频转换指南](../../references/voice-reference-guide.md)确认用户选择的音色路线。已有音色路线从片段 1 起连接用户指定的同一份标准化 `音频1` 或等价音色身份；新建音色路线先确认声音描述，片段 1 不连接音频参考，从片段 2 起连接由片段 1 建立的统一音色锚点。
3. 是否已按[人物参考图指南](../../references/character-reference-image-guide.md)根据完整讲稿规划本片实际需要的关键人物数量；数量完全由影片内容决定，其余一次性人物作为没有固定形象的群演。
4. 全片人物清单是否已经完成；每个主要人物是否都有独立、已确认且足以稳定身份的人物参考图。
5. “人物—人物参考节点—出现片段”对应表是否完整，当前节点是否只连接了本片段实际需要保持身份的关键人物参考图。
6. 当前片段唯一的知识任务、情绪任务或叙事任务。
7. 计划用哪些可见动作把抽象旁白转化为画面。

不要一边改旁白一边写分镜。旁白先定稿，再设计镜头；镜头不得补救旁白缺少的关键事实。

## Prompt 的固定顺序

每个片段都按同一结构独立构造完整 Prompt：

1. 当前音频的音色参考职责；没有音频参考时省略。
2. 参考图片的编号与人物主体定义。
3. 旁白语言、音色来源、语速和当前片段准确正文。
4. 必要的全局画面要求。
5. 按事件顺序排列的镜头。

标准结构：

```markdown
音频1仅用于参考{当前项目已经确认的音色特征}。

参考图1为青年主角的人物参考图。将参考图1中具有{2–3 个稳定静态特征}的青年定义为“青年主角”。视频中的青年主角参考图1的人物形象。

画外旁白使用中文，以音频1的音色，用{当前项目确认的语速与表达方式}，完整、准确、按原顺序说出{当前片段的准确旁白}。{当前项目确认的声音与背景音乐约束}

所有镜头采用{已确认 style 的稳定视觉语言}。本片段的具体场景使用{地点、时代、空间结构、天气、材质、色彩、光线与渲染方式}；未单独提供身份参考的人物使用同一视觉媒介和造型体系，但不复制青年主角的具体脸、发型和服装。

镜头 1：
[景别或机位 + 主体 + 场景 + 起始状态 → 动作、运动与变化过程 → 结束状态 + 完整运镜过程]

镜头 2：
[景别或机位 + 主体 + 场景 + 起始状态 → 动作、运动与变化过程 → 结束状态 + 完整运镜过程]

镜头 3：
[景别或机位 + 主体 + 场景 + 起始状态 → 动作、运动与变化过程 → 结束状态 + 完整运镜过程]
```

15 秒片段一般扩展到镜头 5；根据内容节奏增减，不机械固定为三个。旁白正文只出现一次，放在 `{}` 中；镜头段落只写画面，不重复旁白。

已有音色路线的片段 1 也使用上述“音频1”职责，并在后续所有片段继续连接用户指定的同一份库内参考。只有新建音色路线的片段 1 省略“音频1”职责，直接写入用户为本期确认的声音特征，让音色随片段 1 一起生成；从片段 2 开始，使用由片段 1 剥离并确认的纯音频。选择、建立、转换或更换音色的完整流程只在[音色参考与音频转换指南](../../references/voice-reference-guide.md)中维护。

## 参考素材职责

### 人物数量与人物参考图

- 完整遵循[人物参考图指南](../../references/character-reference-image-guide.md)：根据完整讲稿判断影片中实际需要稳定身份的关键人物数量，不机械固定人数；没有固定身份的其他人物作为群演。
- 每个关键人物分别使用一张已确认、足以稳定身份的人物参考图；默认从单人物单视图开始，只有镜头需要时才补多视图。动画视频不生成或连接独立场景图、画风参考图或风格参考图。
- 输入视频节点时，只连接当前片段实际需要的关键人物参考图。Prompt 首段必须逐张说明“参考图 N 为哪个人物的人物参考图”，再明确“角色 X 参考图 N 的人物形象”。
- 按 Seedance 官方主体定义方法，用 2–3 个稳定静态特征把每张人物图定义为唯一角色标签，后续每镜持续使用该标签，不改用容易混淆的代词。

### 音频的音色参考

- 只引用已经实际连接的 `音频1`，并说明它“仅用于参考音色”；只补充用户已经确认且确有必要的声音特征。
- 当前片段正文只由当前 Prompt 中 `{}` 内的旁白决定，不复述样本原台词，也不借用其语义。
- 即使只有一份参考音频，也一般使用实时 schema 支持的全能参考模式 `mixed2video`，不得仅因音频数量为 1 就选择 `audio2video`。`modeType` 是显式执行参数，不写进创作 Prompt。
- 输入模式、音频格式、片段 1 建锚和后续片段使用统一遵循[音色参考与音频转换指南](../../references/voice-reference-guide.md)，不在本指南重复。

### 场景与风格文字描述

- 不生成或连接独立场景图、画风参考图或风格参考图。每个片段根据自身场景需求，在 Prompt 中直接写清地点、时代、空间结构、天气、主体与环境材质、色彩关系、光源方向、空气层次和渲染方式。
- 不同片段可以使用完全不同的场景内容、构图、天气和强调色。整体一致性来自所选 style 的稳定媒介、造型、材质、线条、色彩原则和运动语言，而不是复刻一张统一场景图。
- 场景描述必须服务当前片段的具体事件，不复制其他片段的地点、道具和构图来追求表面统一。
- 只接入真实需要的人物和音频素材。不要为了“可能有帮助”把无关图片、视频或音频连接给模型。

### 人物参考与群演画风

- 在完整分镜确认后先列出全片人物。凡是需要跨镜头或跨片段保持身份，或在单个重要片段中必须稳定辨认的关键人物，都先生成独立人物参考图并由用户确认；数量由内容决定。
- 每张人物参考图只包含一个清楚、无遮挡的人物，脸部、发型、体型、服装和主要材质足以辨认。背景可以是纯色、柔和渐变或不抢主体的简洁环境；背面、侧面、表情表和姿态表按实际镜头需求增加。
- 不允许主要人物第一次在视频生成时只靠文字出现。缺人物参考图就停止生成并补图，不使用相似人物、临时描述或其他角色参考代替。
- 为每个视频节点只连接本片段实际需要的关键人物参考图，并逐张定义唯一角色标签；不再追加场景或画风参考图。
- 多视图人物素材可能加剧 ID 漂移或生成重复人物，因此先用最少而充分的参考验证片段 1。若出现换脸、同款分身、背面失真或服装漂移，必须保留任务记录并报告，再针对真实问题补充参考。
- 群演、路人和一次性背景人物可以没有独立身份参考，但 Prompt 必须明确其使用与关键人物相同的视觉媒介、角色造型语言和渲染体系，同时不复制任何参考人物的具体脸部、发型和服装。
- 群演与主要人物必须使用同一种视觉媒介和渲染体系。主要人物为风格化 3D 动漫时，群演也应是同套风格化 3D 动漫；不得漂移成写实真人、平面插画或另一种卡通风格。
- 在生成前维护“人物—人物参考节点—出现片段”对应表；新增一个跨镜头或跨片段持续出现的角色时，先判断其是否已经升级为主要人物。若是，先补人物参考图，再修改相关视频节点。

### 不因能力臆测主动降级内容

- 不要因为担心模型无法遵循复杂人物设定，就主动删去人物、把人物替换成物件隐喻，或把已经确认的角色造型简化成另一种风格。当前模型能够结合独立人物参考与清晰的主体定义处理具有服装、道具和身份特征的角色；按实际片段连接所需参考，并持续使用唯一角色标签。
- 多个人物或跨片段复现人物时，为每个主要人物建立并确认独立人物参考图，再维护人物与片段的对应关系。只有实时 schema、素材数量上限或实际生成结果暴露明确问题时，才调整素材组合；不要仅凭对模型能力的主观担忧预先降低画面复杂度。
- 旁白和台词可以由提示词中的准确正文直接驱动。本项目继续用 `{}` 标出必须逐字生成的旁白或台词，并把它作为当前片段声音内容的唯一来源；不要因为担心模型无法朗读长句而擅自删词、改写或改成后期配音。
- 不用画内小字、标签、卡片文字、墙面文字或气泡文字解释旁白中的概念。把含义改写成具体事件、人物行动、物体关系和直接后果；颜色与光线只辅助表达，不能单独代替事件。只有用户明确要求标题、字幕、Logo 或其他画内文字时，才在 Prompt 中写准确文字及其位置和出现方式。

### 具象事件优先

- 旁白可以讨论哲学、心理或其他抽象思想，但画面必须优先讲一件观众能够直接看懂的具体事情。每个知识判断都先回答：谁在什么可识别地点遇到了什么问题，做了什么，其他人或物体怎样回应，最后出现什么可观察结果。
- 优先使用生活、工作、家庭、学校、街道、商店、车站、工坊、法庭、市场、历史现场或其他真实可辨的环境；让人物通过选择、交谈、等待、追赶、交换、拒绝、协作、失误、修复和承担后果来体现思想。
- 默认不用空无空间中的孤立人物、漂浮几何体、能量流、发光符号、无来源的锁链与方框、巨大器官、无限走廊、宇宙尺度意象、纯色块变化或物体无缘由变形来直接代表思想。这类概念性画面不容易形成清楚的动画事件。
- 隐喻或象征只能作为具体事件中的短暂辅助细节，不能成为整镜或连续多个镜头的主要内容；去掉象征后，人物行为及其因果结果仍应足以表达旁白。
- 视觉风格可以夸张、手绘、黏土化或三维动画化，但叙事对象和动作仍要具体。风格化不等于概念化，也不能用“有哲思感”“抽象空间”“意识世界”等词代替可拍摄的事件。
- 写完每镜后检查：一个不了解旁白的观众，是否能仅凭画面说清正在发生什么事情。若只能感到情绪或猜测象征含义，重新设计成更具象的场景。

## 镜头设计

### 镜头数量与节奏

- 15 秒片段一般规划 5 个镜头，让当前语言下长度合适的旁白持续获得新的视觉信息；中文默认约 60 个汉字，英文默认约 32 个单词。
- 五镜是当前已经验证的默认节奏，不是强制把一个自然长动作切碎。需要舒缓长动作时可以减少镜头，需要非常紧凑的蒙太奇时可以增加。
- 6–7 个镜头只用于非常紧凑的蒙太奇；此时降低每一镜的动作和运镜复杂度。
- 不默认写“0–3 秒”等精确时间段。按“镜头 1、镜头 2……”表达事件顺序，让模型自然分配节奏。

### 导演可执行的专业画面描述

- 不用固定的主体数、动作数、道具数或视觉中心数量限制画面。画面复杂度由旁白内容、叙事目的和已确认风格决定；二维动画也可以表现多人、复杂空间、并行动作和完整环境。
- 像撰写动画电影或 3D 电影的导演分镜说明一样，使用自然、专业、可拍摄的电影语言。二维风格写清平面层级、造型、动作路径和逐帧变化；三维风格写清空间纵深、角色调度、摄影机运动、光影和环境反馈。
- 每镜完整定义初始构图、摄影机位置与视角、人物和物体的空间关系、动作发生顺序、运动方向与路径、速度和幅度、接触或形变反馈、环境变化、运镜过程、最终构图以及切镜条件。
- 多主体、多动作或多阶段变化可以放在同一镜头，但必须逐项说明谁先做什么、谁同时做什么、各自从哪里移动到哪里、动作如何互相影响，以及每一步完成后的可见状态。
- 目标不是删减画面信息，而是消除执行歧义。描述完成后，任何动画导演、摄影指导或分镜师都应能仅凭文字还原出高度一致的镜头，不需要自行补充关键构图、调度、运动或变化。

### 按需建立空间连续性说明

只有当多个镜头反复拍摄同一个可识别空间，并且需要保持空间连续性时，才在分镜前写一段这些镜头共同遵守的空间说明。可以按需固定：

1. 场景的基本形状与尺度。
2. 主体、大型家具、门窗和背景物分别位于哪个方向。
3. 关键道具从左到右或从前到后的固定排列。
4. 主光源来自哪里，冷暖光分别照亮哪些表面。
5. 哪些空间关系与物品位置在切镜后保持不变。

空间说明负责同一地点的连续性，每个相关镜头只从既定空间选择机位并推动动作。不要在这些镜头中重新描述一套略有不同的房间，否则模型容易把它们理解成不同场景。

15 秒只是片段时长，不代表五个镜头必须处于同一地点或同一条连续时间线。片段可以通过硬切呈现多个完全独立的空间、并列具体案例或跨时空事件蒙太奇。此时不建立跨空间的统一布局，也不强求前后状态承接；只需为每个镜头分别写清新场景、主体、起始状态、可见变化和终点。

### 每一镜必须写清的内容

每个镜头都写清：

1. 谁或什么是主体。
2. 主体位于什么场景、处于什么起始状态。
3. 主体或场景发生什么清楚可见的变化。
4. 变化最终落到什么新的画面状态。
5. 使用什么景别、机位和运镜；如有复合运镜，写清各阶段顺序。

动作可以低缓，但必须产生可见结果。优先使用位移、姿势明显改变、物体移动、拆开、聚合、破裂、变形、门窗开启、场景搭建或空间重构；不要只依赖呼吸、迟疑、细微表情或缓慢光影。

一个镜头可以包含连续动作链、并行动作和环境变化。按时间顺序写清每个阶段的起点、执行者、动作路径、与其他主体的关系、可见反馈和落点；如果无法在片段时长内把这些阶段逐项描述清楚，再拆成多个镜头，不按固定动作数量机械拆分。

### 画面必须具体到没有想象偏差

把每个镜头当成写给一位无法追问的摄影师和美术：他只能照字面执行，看不到你脑中的画面。凡是留给模型自由发挥的空白，都会变成画面漂移和片段之间的不连贯。因此每一镜都要写到“换一个人读也会摆出几乎相同的画面”的程度。

1. 主体要具体到可辨认：谁、外形、朝向、在画面中的位置和景别，不用“一个人”“某物”“抽象的它”这类模糊指代。同一主体在相邻镜头保持同一称呼和同一外形。
2. 空间要具体：场景是什么地方、主体处在前景中景还是背景、光从哪个方向来。用几何关系写明摄影机位于门口、窗外、人物左侧或桌面正上方，与主体眼睛、肩膀或桌面多高，朝向哪里；必要时说明画面左、中、右分别出现什么，让构图唯一确定。
3. 动作按官方“肢体细化 + 程度量化”写：指明动到哪个部位（手、头、肩、脚、躯干），以及幅度、速度、力度和方向，例如“缓慢抬起右手到胸前”，而不是“他动了一下”。
4. 抽象概念和情绪必须落实为具体事件及其后果，不能直接把“痛苦”“欲望”“意志”“自由”当画面，也不要只把它们替换成孤立象征物。先设计一个人物在可识别场景中做出选择并承担结果的过程，再写清参与者、物体、动作和因果关系。
5. 起点、变化、终点三者都要是具体可见的画面状态，中间的变化过程也要交代清楚，不允许出现“慢慢变化”“逐渐出现”这类没有指明变成什么、如何变的措辞。
6. 宁可把一镜写长写死，也不要为了简洁留下多种合理解读；删减时删的是重复风格词和空泛质量词，不是使画面唯一确定的具体信息。

可以使用固定机位、单一运镜或符合电影调度的复合运镜。使用复合运镜时，必须写清先后阶段、每一阶段的方向、摄影机与主体的相对关系、衔接点和最终机位，不能只堆叠“推拉摇移环绕”等术语。

### 运镜方向与起止位置

- 每次运镜都写清摄影机的起始位置、移动方向、参照对象和结束位置；只写“下降”“向前跟进”“横移”“环绕”或“轻微推近”仍然不够明确。
- 推镜或拉镜写明摄影机沿镜头轴朝向哪个主体靠近或远离，并说明结束景别，例如“摄影机从青年正前方的中景位置沿镜头轴向青年靠近，停在胸部近景”。
- 横移或跟拍同时写明画面方向和摄影机与主体的相对关系，例如“青年从画面左侧走向右侧；摄影机位于青年正侧面，与他等速向画面右侧平移，始终保持中景”。
- 上升或下降写明垂直起点、终点与俯仰关系，例如“摄影机从青年肩部高度垂直升到路灯上方，镜头持续向下俯拍青年”。
- 摇镜写明从哪个对象或画面区域摇向哪个对象或区域；环绕写明从主体哪一侧开始、绕行方向和停止在哪一侧。若这些信息没有叙事价值，改用固定机位。
- “画面左／右／上／下”描述屏幕方向；“人物左／右、前／后”描述主体自身方向。两者可能不同，不能混写。必要时同时写明人物朝向，避免左右反转。

### 硬切与连续性

- 镜头之间默认像电影一样直接硬切，并主动改变景别、角度、运动方向、场景或视觉焦点。
- 不写擦除、形变、融化、线条延伸、颜色接力或其他装饰性转场。只有连续性本身是创作重点的特殊长镜头，尤其长时间动作或打斗编排，才设计不中断的镜头调度。
- 连续性不等于所有镜头平滑过渡，也不等于始终保持同一构图。
- 每一镜都要有“起点 → 运动 → 终点”；切镜前让动作落地，下一镜从新的信息或新的动作继续。
- 只有相邻镜头有意拆分同一条连续动作时，下一镜才明确承接上一镜已经完成的状态，例如“从上一镜笔尖悬停在纸面上方的状态开始落笔”。若硬切到独立场景、并列具体案例或不同时间地点，则直接定义新的起始状态，不需要承接上一镜。
- 不要让上一镜完成推近，下一镜回到相似中景再次推近；也不要重复完成过的抬头、起身、聚焦、放大、拉扯、释放或开门动作。
- 只有重复本身具有明确叙事意义时才允许重置，并在 Prompt 中说明它是新的、有意设计的重复。

## 满幅构图与画幅设置

- 目标画幅和分辨率来自用户要求或当前项目配置。每次创建或重生成视频节点都通过当前 CLI 显式传递实际 `ratio` 与 `resolution`，不得依赖画布旧值、复制节点参数或模型默认值。
- `ratio`、`resolution` 和片段时长通过 CLI 参数传递，不在 Prompt 中重复横竖屏比例、分辨率或时长。
- 默认避免使用“超宽银幕”“变形宽银幕”“电影遮幅”“letterbox”等容易诱发内部黑边的描述。
- 某一风格或片段曾出现内部遮幅时，在重生成 Prompt 中加入正向构图要求：“所有镜头采用满幅画面，场景与背景完整覆盖整个可见构图区域。”不要改写成技术参数。

## 不要写进 Prompt 的内容

- 不提交“片段 1：”等外部管理标签；实际 Prompt 直接从参考素材职责或旁白要求开始。
- 不重复 LibTV 已传递的时长、比例、分辨率、声音开关、数量和 `modeType`。
- 不在 Prompt 中引用不存在的场景或画风参考图。每个片段直接写清当前场景所需的视觉风格，但避免重复堆叠同义质量词。
- 不默认加入无字幕、无 Logo、无水印、不做口型或无背景音乐等项目选择。只写当前项目或用户明确要求的必要约束，避免堆叠冗长负面词。
- 不把完整剧本、创作解释、字数统计或镜头设计理由一起提交给模型。
- 不把风格参考误写成首帧、尾帧、关键帧或需要复刻的构图。
- 不用卡片、路牌、墙面、气泡或漂浮标签上的小字替代可见叙事；除非用户明确要求画内文字，否则不要在视频 Prompt 中要求生成任何小字。
- 不堆叠“高级、震撼、电影感、史诗、唯美”等不能转化为具体画面的空泛质量词。

## 对话中的交付格式

向用户展示多个 Prompt 时，使用清楚的外部标题和空行，但不使用 `text` 或 `plaintext` 代码块：

```markdown
### 片段 1

*旁白：60 个汉字*

参考图1为青年主角的人物参考图。将参考图1中具有{稳定特征}的青年定义为“青年主角”。视频中的青年主角参考图1的人物形象。

所有镜头采用{已确认 style 的稳定视觉语言}。本片段发生在{具体地点与时代}，使用{具体材质、色彩、光线、空气层次与渲染方式}。

画外旁白使用中文。旁白为……

……
```

“片段 1”和字数只用于审稿；复制到 LibTV 前必须剥离。实际旁白仍以 `{}` 中的文本为唯一提交内容。

## Markdown 落盘

所需人物参考图确认后，按片段编号逐个编写视频 Prompt。每完成一个片段，立即保存为一个独立的 Markdown 文件，不得等全部片段写完后才统一落盘，也不得把多个片段合并在一份总文档中：

1. 优先遵循当前项目已经规定的目录、文件名和版本规则；没有规定时，统一保存到 `<作品目录>/production-docs/`，使用补零编号命名为 `片段01.md`、`片段02.md`……，不把具体作品 Prompt 写入 skill 目录。
2. 每个文件只记录一个片段，至少包含视频标题、片段编号、已确认视觉风格、该片段实际使用的参考素材职责、定稿旁白与汉字数，以及该片段的完整视频 Prompt。
3. 审稿用的“片段 N”和字数可以保留为文件结构，但另行标明实际提交内容，确保复制到模型前能够剥离外部管理标签。
4. 编写顺序、文件编号、旁白片段编号和后续视频节点编号必须一致；缺失、中断或重复编号时先修正，再进入生成。
5. 对话中对某个片段的修改只同步写回对应的独立文件；需要保留历史版本时遵循当前项目约定创建新版本，不能让聊天中的定稿与磁盘文件互相矛盾。
6. 每个文件保存完成后向用户返回文件路径，便于逐片审阅和继续生产。

确认后的 `旁白.md`、人物与参考素材计划、每个片段的独立 Prompt 以及同一作品的其他生产 Markdown 文档全部平铺在上述同一个目录，不为视频 Prompt 再建立嵌套子目录。

## 提交前检查

- 音色路线是否已经由用户明确选择？已有音色路线是否从片段 1 起连接用户指定的同一份库内标准化音频；新建音色路线的片段 1 是否保持不连接音频，并从片段 2 起连接由已确认片段 1 建立的纯音频，而不是视频本身或其他候选音频？
- 音频承担音色参考职责时，是否即使只有一份参考音频也显式使用实时 schema 支持的 `mixed2video`，而没有误用 `audio2video`？平台要求视觉输入时，是否只连接当前片段真实需要的有效人物或视频参考？
- 上游素材顺序是否与 `音频1` 和每张人物参考图的编号一致？
- Prompt 是否明确 `音频1` 只负责当前项目已经确认的音色，而没有把其原台词或语义带入当前片段？
- 是否已经根据完整讲稿判断本片实际需要几个关键人物，而不是机械固定数量或为群演生成参考图？
- 全片人物清单和“人物—人物参考节点—出现片段”对应表是否已经完成？
- 当前片段的所有主要人物是否都有已确认人物参考图，并实际连接到当前视频节点？
- 每张人物参考图是否只包含一个清楚、无遮挡的人物，身份特征是否足以满足当前镜头；是否只在确有需要时补充多视图？
- 是否误生成或连接了独立场景图、画风参考图或风格参考图？
- Prompt 开头是否逐张标明“参考图 N 为哪个人物”，是否用稳定特征定义唯一角色标签，并明确“角色 X 参考图 N 的人物形象”？
- 无独立身份参考的群演是否明确使用同一视觉媒介、角色造型语言和渲染体系，同时不复制关键人物的具体外貌？
- 当前片段是否按自身叙事需求写清具体场景地点、时代、空间、天气、材质、色彩、光线和渲染方式？
- 当前视频节点是否显式设置项目要求的 `ratio` 与 `resolution`，而不是继承旧值或模型默认值？
- 是否只引用了真实连接的素材？
- 旁白是否与定稿逐字一致，只出现一次，并放在 `{}` 中？
- 是否误把“片段 N”或字数标签带进 Prompt？
- 当前片段是否已单独保存为对应编号的 Markdown 文件，并且没有与其他片段合并？
- 每镜是否有主体、起始状态、可见变化和结束状态？
- 每镜是否具体到没有想象偏差：主体、朝向、位置、景别、机位、光向、动作部位与幅度速度是否都唯一确定，换一个人读也会摆出几乎相同的画面？
- 镜头复杂度是否由内容和风格决定，而不是受固定主体数、动作数、道具数或视觉中心数量限制？多主体和多阶段动作的空间关系、发生顺序、相互影响与最终状态是否逐项写清？
- 每个思想是否已经落实为发生在可识别场景中的具体事件、人物行动、物体关系和可观察结果？
- 是否仍用空无空间、漂浮符号、能量流、无来源的锁链或方框、巨大器官、无限走廊、宇宙意象、纯色变化或无缘由形变承担主要表达？隐喻与象征是否只作为具体事件的辅助细节？
- 一个不了解旁白的观众能否仅凭画面说清正在发生什么事情，而不是只能猜测象征含义？
- 是否残留“慢慢变化”“逐渐出现”“动了一下”等没有指明变成什么、如何变的模糊措辞？
- 15 秒片段是否一般规划为 5 个镜头，并保证每镜包含的动作与变化都能在片段时长内完整描述和执行？
- 若多个镜头反复拍摄同一个空间且连续性重要，是否给出必要的空间连续性说明，并避免道具位置、门窗方位与光线方向互相冲突？
- 每个机位是否写清摄影机位置、高度、朝向和画面左中右的空间分布？
- 若有意把同一条连续动作拆到多个镜头，下一镜是否明确承接已完成状态？若是独立场景，是否避免强行制造无关的状态承接？
- 相邻镜头是否提供新信息，而不是重启同一个动作或运镜？
- 运镜是否明确写出摄影机起点、移动方向、参照对象、终点和结束景别？若使用复合运镜，阶段顺序与衔接点是否清楚？屏幕方向与人物自身方向是否区分清楚？镜头数量是否适合 15 秒？
- 是否误写精确秒数、首尾帧、技术参数或重复画风描述？
- 是否只写入用户明确要求的声音、字幕、Logo、水印和背景音乐约束？
- 是否用卡片、路牌、墙面、气泡或漂浮标签上的小字解释概念？若用户没有明确要求画内文字，是否已经改为动作或物体关系？
- 若历史输出出现内部黑边，是否加入了满幅画面的正向构图要求？

## 生成后确认

默认只确认：

- 每个视频任务已成功返回终态。
- 节点 ID、任务 ID 和资源 URL 均存在并已记录。
- 返回资源可以下载，所有视频已直接保存到当前作品的 `video/` 目录。

默认不播放、不抽帧、不听写，也不检查旁白、音色、人物、画风、动作、实际画幅或片尾音频。只有用户明确要求，或任务失败、资源缺失、平台返回异常时，才执行针对性内容检查。

## 视频文件落盘

- 当前作品的所有独立视频片段和最终合成视频统一放在 `<作品目录>/video/`。
- 文件直接平铺在 `video/` 下，不创建 `segments/`、`segment-xx-*` 或其他逐片子目录。
- 片段文件使用补零编号保持顺序，例如 `片段01.mp4`、`片段02.mp4`；最终成片使用可识别主题的文件名。
