## 当前状态与核心目标

本文档是 Storytime Animation 的首版已验证流程，已经完成一支五片段英文 Storytime 作品的实际生成与用户质量确认。最终剪辑由用户在剪辑工具中完成，不把 Agent 自动拼接视为本 Mode 验证完成的必要条件。执行时应保留故事采集、讲稿修改、人物设计、音色、片段节奏和生成失败记录；只将实际作品证明有效且经用户确认的方法固化为稳定规则。

以讲述者的第一人称声音和个人视角为主轴，用动画重现自己、身边人或经过明确改编的故事。核心不是“用第一人称念一篇文章”，而是让观众通过稳定的讲述者身份、具体细节、事件升级和当事人的回看，感到“这件事只能由这个人这样讲”。

## 适用边界

在以下情况选择本 Mode：

- 创作者要讲述自己亲历的事情。
- 讲述者要讲身边人的故事，并已明确自己与故事的关系。
- 真实经历经过匿名、合并人物或调整非关键细节后，仍由当事人视角讲述。
- 虚构故事明确以第一人称故事作品呈现，不冒充真实亲历。

如果个人经历只是开场例子，整支视频的主要目标仍是解释一个概念，使用 [Animated Explainer](../animated-explainer/workflow.md)。

## 必须输入与故事采集

不要只索取“主题、受众、时长”就直接写稿。先通过少量、逐轮的问题采集故事，避免一次抛出长问卷。至少弄清：

- 故事是谁经历的，讲述者与当事人是什么关系。
- 事情发生在什么时候、什么地方，当时的人物分别知道什么。
- 当时的“我”想得到、完成或避免什么。
- 最初的阻碍是什么，事情后来怎样一步步变糟、变好或变得更荒谬。
- 哪一刻改变了事情的方向，最终直接后果是什么。
- 哪些具体细节最好笑、尴尬、意外、温暖、可怕或难忘。
- 现在的讲述者如何看待当时的自己，这个看法是如何变化的。
- 哪些人物、地点、对话或事件不得公开，哪些可以改编。
- 预期成片更偏搞笑、温暖、尴尬、惊险、忧伤还是反思。

采集时优先追问可以被画出来的事实：人物站在哪里、手中拿着什么、谁先说了什么、哪个动作引起了什么后果。不要只收集“我很尴尬”“气氛很奇怪”这类无法还原事件的概括。

## 真实性、改编与隐私

写作前建立简短的事实边界，分别记录：

- **可确认记忆**：讲述者能确认发生过的事件与细节。
- **不确定记忆**：时间、原话或先后顺序已无法确认的部分。
- **保护性改编**：为匿名、合并人物、模糊地点或保护当事人所做的修改。
- **戏剧化重构**：为叙事清楚而压缩时间、重排非关键顺序或重建大意相同的对话。
- **禁止使用**：用户明确不允许公开或无法安全处理的信息。

不擅自补写真实人物的动机、病史、私密关系、犯罪行为或伤害性细节。不把推测写成亲历事实，不为增加戏剧性虚构关键伤害、指控或后果。改编会改变故事实质时，先向用户确认。

## 故事骨架

先用一句话定义故事：

> 当我想要____时，____破坏了原计划，最后我____。

再按真实事件的需要选择下列节点，不机械要求每支视频全部具备：

1. **冷开场**：直接呈现最反常、紧张、尴尬或好笑的一刻，但不可脱离正文骗取注意。
2. **回到起点**：交代当时的“我”是谁、在哪里，以及为什么会走到冷开场那一刻。
3. **目标与预期**：让观众知道当时的“我”想完成什么，并理解失败的代价。
4. **升级**：用新动作、新信息或新后果不断改变局面，不只是重复“越来越紧张”。
5. **转折**：一个决定、发现或意外让原计划不再可行。
6. **高潮与直接后果**：让当时的“我”做出行动并承受立即结果，不用旁白跳过最关键的事件。
7. **余波**：说明事情实际怎样收场，人物关系或讲述者的看法发生了什么变化。
8. **现在的回看或尾梗**：从现在的讲述者视角结束，优先落在一个具体回声、动作或余韵上，不强行总结人生道理。

每个节点都必须改变观众所知道的信息、当时的“我”能做的选择，或事件已造成的后果。没有发生任何变化的节点应删除或合并。

## 第一人称讲稿

- 使用讲述者实际可能采用的现代口语，像向一个熟悉的听众讲事，不写成主持稿、散文朗诵或小说旁白。
- 保持“当时的我知道什么”与“现在的我知道什么”的区别。只有现在的讲述者可以使用事后理解和评价。
- 优先使用可视化的动词、道具、位置、对话和结果，不用连续的情绪形容词代替事件。
- 允许犹豫、自嘲、插话、短暂回看和观点变化，但每一次偏离都应增加人物信息、笑点或故事理解。
- 笑点优先来自错误预期、判断失误、人物反应和可见后果，不依赖连续网络梗、吐槽句或无关反应镜头。
- 只保留推动局面、暴露人物或在后文产生回响的对话。无法确认原话时，不用引号伪装成精确记忆。
- 不为了证明故事“有意义”强行添加道德结论，也不把所有尴尬经历改写成成长鸡汤。

先写完整故事讲稿，再按语义与故事节点拆分。Storytime 使用 15 秒英文片段时，默认目标为 30 个实际朗读单词，通常保持在 28–32 个；超过 32 个单词时，生成前必须先缩短并交给用户确认，只有用户明确接受更快语速时才可保留。计数按实际朗读单词计算，破折号两侧即使没有空格也分别计词。Storytime 需要给自嘲、惊讶、尴尬和情绪转折留出表演时间，不用加快语速掩盖过长旁白。

## 讲述者身份与人物参考

讲述者不只是一条声音，而是 Storytime 的持续主角。在视觉设计前确认：

- 讲述者的动画化形象、辨识特征和固定称呼。
- 故事发生时的过去形象是否与现在形象显著不同。
- 讲述者的性格、自我看法、语气和常见反应，但不把人格压缩成固定口头禅。
- 哪些配角会跨镜头或跨片段重复出现，哪些只是一次性群演。

先与用户确认本期要沿用已有形象，还是共同设计一个新形象。已有形象可以来自用户自己的素材或 [Storytime 人物形象库](characters/character-library.md)；选择库内形象时仍需确认它是否适合本期讲述者，不设置默认人物。

新形象采用对话式共创：先确认年龄感、体型与头身关系、脸部与发型、服装、线条与色彩、喜剧或情绪气质，再生成少量候选。不要一开始用固定问卷或严格模板限制设计。用户确认后，询问是否将它保存到 Storytime 人物形象库；只有用户明确同意时，才保存标准化图片、人物卡和可复用生成说明，不自动收录每期私有人物。

人物参考图完整执行 [人物参考图指南](../../references/character-reference-image-guide.md)。默认一张清楚的单人物全身图即可，背景可以是纯色或柔和简洁背景；只有剧情确实需要背面、侧面、复杂转身或换装时才补多视图。童年、少年与成年版本只在外形差异大到模型无法可靠维持时，才作为不同参考人物规划。本次五片段作品已验证：同一张成年卡通 avatar 可以在小学、中学和成年重现中继续维持身份，因此不要仅因时间跨度自动拆分年龄版本。

## 讲述层与重现层

为每个故事片段明确选择一种或组合两种画面层次：

- **讲述层**：现在的讲述者直接面向观众表达、补充、吐槽、纠正或回看。画面必须有具体表演、道具或反应，不让人物长时间站立念稿。
- **重现层**：过去的“我”和其他人物在当时的场景中完成事件。严格遵守当时视角能够知道的信息，不让画面客观呈现无法确认的他人动机。

切换必须有叙事职责。从讲述层切到重现层，用于让观众亲眼看到事情如何发生；从重现层切回讲述层，用于暴露现在的讲述者怎样评价当时的自己、制造反差或补充时间跳跃。不为追求“节奏快”而无意义地来回切换。

讲述层不等于“人物固定在画面中央的播报层”。讲述者可以根据当前场景与笑点需要位于中央、画面一侧、左下角或右下角，也可以直接成为家庭、学校、卧室或职场场景中的一个角色，在继续参与动作的同时转头看向镜头讲述。每个镜头都应重新决定讲述者的景别、站位、视线与环境关系；只有同一连续镜头确实需要保持构图时，才锁定其屏幕位置。无论站位如何变化，都必须维持人物身份、造型和声音的一致性，并让观众清楚辨认出谁在讲故事。

同一片段可以根据故事节拍交替使用三种关系：讲述者正面面向观众说话、讲述者在第一人称视角镜头中与镜头对视、讲述者作为场景中的角色参与互动并在需要时转向观众。三者用于制造亲近感、重现事件和形成喜剧反差，不要求每个片段机械地全部使用，也不把其中任何一种固定为默认构图模板。

## 片段、镜头与 Prompt

开始视频 Prompt 前完整读取：

- 用户已选择的 [style](../../SKILL.md#共享-style-与参考资产)
- [共享视频生成 Prompt 指南](../../references/video-generation-prompt-guide.md)
- [Seedance 2.0 官方提示词指南](../../references/official-seedance-2.0-prompt-guide.md)

对每个片段先记录：

- 这一段在故事中改变了什么。
- 属于讲述层、重现层，还是有理由的两层切换。
- 开始时人物知道什么、想做什么，结束时信息、选择或后果发生了什么变化。
- 当前片段实际需要哪些关键人物参考。
- 需要维持哪些空间、道具、服装和动作连续性。

镜头数量由故事节拍和可执行动作决定。15 秒 Storytime 片段通常使用 3–5 镜，本次验证表明约 4 个具体场景是稳定起点；不为凑镜头数拆散情绪留白或同一条必须连续的喜剧动作。每镜仍需让导演看懂场景、人物位置、动作、观众关系、情绪变化与切镜点，但不必把简单动作扩写成防御性规格书。

Prompt 保持简洁。人物身份、所选 style、音色职责和转场规则在全局位置各写一次；每镜只补充当前场景、人物站位与视线、必要动作、互动和情绪变化。不在每镜重复人物外貌、硬切、style 或长串负面约束。Prompt 应像一份可执行的导演提纲，而不是逐项防错清单。

不连续场景之间默认硬切，不使用渐变或叠化转场。在 Prompt 的全局说明中简洁写明一次即可，不在每个镜头中重复，也不堆叠冗长的负面转场词。只有连续动作本身是创作重点的特殊长镜头，尤其长时间动作或打斗编排，才有理由不硬切。

每完成一个片段 Prompt，立即按视频提示词指南保存为作品统一文档目录中的独立 Markdown 文件。

## 音色与声音身份

第一人称声音是讲述者身份的一部分。在正式生成前，仍完整执行主 `SKILL.md` 的音色路线和 [音色参考指南](../../references/voice-reference-guide.md)，不默认选择某个内置音色。

音频参考只锁定讲述者的声音身份，不代替当前片段的情绪表演。每个片段的 Prompt 应根据故事变化，用简洁语言说明声音从什么状态开始、在哪个词句发生明显转折、最后落到什么情绪，并要求自然的轻重、停顿与音高变化；不让稳定音色变成平淡朗读，也不逐词堆叠过度细碎的表演指令。

选择时优先考虑这个声音能否长期代表讲述者，而不只是本期是否清楚好听。使用用户本人、频道既有讲述者或其他真实人物的声音时，先确认用户拥有使用授权；不根据无授权样本模仿或重建他人身份。

## 完整制作流程

1. 逐轮采集故事，不在信息不足时自行补完事件。
2. 确认真实性、改编、隐私和禁止使用边界。
3. 完成一句话故事定义和故事节点大纲，先交给用户审阅。
4. 确认讲述者形象、声音身份、现在视角与过去视角。
5. 写作完整第一人称讲稿，再按故事节点与生成能力拆分。
6. 将讲稿与拆分结果交给用户确认；确认后保存为作品文档目录中的 `旁白.md`，并注明 Mode 为 `storytime-animation`。
7. 建立“人物—故事时间层—出现片段—参考状态”对应表，并按人物指南生成、确认所有必要人物参考。
8. 为每个片段确定讲述层、重现层、事件变化、当前人物知情范围和必要连续性。
9. 完整读取所选 style、视频提示词指南和 Seedance 官方指南，逐片段编写并保存 Prompt。
10. 返回主 `SKILL.md` 的音色选择、片段 1 确认、音色锁定、后续片段并行生成与下载流程。
11. 全部片段生成并下载后，提示用户使用剪辑工具手动排序和拼接，轻量修剪局部废帧、片尾约 0.1 秒可能出现的画面或声音毛刺，并检查节奏、响度和切点。除非用户明确要求，不把 Agent 自动拼接作为默认步骤。

## 质量门槛与失败条件

以下任一情况存在时，不得进入批量生成：

- 还无法用一句话说明当时的“我”想做什么、什么破坏了计划以及最终后果。
- 故事的真实记忆、不确定部分、保护性改编和禁止使用信息没有分开。
- 讲稿只有情绪概括和事后评价，没有足够的人物选择、具体动作与可见后果。
- 每个节点都在重复同一种情绪，事件、信息、选择与后果没有发生变化。
- 现在的讲述者与过去的“我”的知情范围混乱，或画面把推测的他人动机当作客观事实呈现。
- 讲述者或任一必须稳定识别的配角缺少已确认人物参考。
- 讲述层只是人物站着念稿，重现层只是与旁白无因果关系的动画配图。
- 声音与讲述者身份尚未确认，或尝试使用无授权真人的声音建立音色。
- 片段 1 尚未验证讲述者形象、表演、声音和两层切换的实际效果。

第一支验证作品建议控制为 60–90 秒、一个明确事件、一位讲述者、最多一至两位重要配角和两至三个主要地点；这是降低首次验证变量的建议，不是本 Mode 的永久规格。
