## 基础公式

先判断任务属于哪一种：

- **多模态参考**：从图片、视频或音频提取人物、动作、风格、运镜、环境或音色，再生成新视频。
- **编辑视频**：修改已有视频中的指定部分，未提及部分尽量保持。
- **延长视频**：向前或向后延续已有视频的主体、动作、声音和叙事。

不要把三种任务的指令混写。参考任务使用“参考图片／视频／音频 N 的……”，编辑或延长任务直接指向要处理的视频。

## 多模态参考

为每份输入只声明它实际承担的职责：

- 图片可以负责人物身份、物体外观、场景或视觉风格。
- 视频可以负责动作、运镜、节奏、特效或连续性。
- 音频可以负责音色、说话方式、节奏或声音氛围。

输入素材越多，越要写清编号和职责。不要要求模型从一张人物参考图同时复制人物、背景、构图和动作，除非这些确实都需要保持。

## 编辑视频

写清：

1. 修改哪个视频。
2. 修改什么元素、从什么状态改成什么状态。
3. 修改发生的时间和画面位置。
4. 哪些内容必须保持不变。

局部修改优先使用明确的主体名称、位置和可见属性，不用“把它改好看一点”这类不可执行描述。

## 延长视频

说明向前或向后延长，并定义延长后继续发生的动作、人物位置、摄影机方向、声音状态和结束画面。延长适合连续动作或同一场景，不适合把明显不同的地点和时间硬塞进同一连续视频。

## 定义主体

使用 2–3 个稳定静态特征定义人物或物体，并在全文持续使用同一标签。例如：

> 将图片1中金色微卷短发、湖蓝上衣、白色圆身的青年定义为“青年讲述者”。视频中的青年讲述者参考图片1的人物形象。

不要在后续镜头中不断改用“他”“那个男人”“主角”等不同称呼。人物参考图默认从一个人物、一个清楚视图开始；多视图只在实际需要时补充。

## 使用分镜时序

多镜头 Prompt 按事件顺序写“镜头 1、镜头 2……”即可。每镜至少让人看懂：

- 起始场景和人物位置
- 当前可见动作或互动
- 摄影机与主体的关系
- 动作造成的变化或结束状态
- 切镜点

不必为每镜机械分配精确秒数。镜头数量和描述长度服从片段内容。

## 动作描述要求

动作使用可观察的动词，写清主体、方向、路径、速度、接触和结果。复杂动作按先后或同时关系说明，不用“人物自然地忙碌起来”“镜头充满活力”等抽象概括代替调度。

对于简单 Storytime 片段，保持导演提纲式简洁；只有多人交互、复杂连续动作或空间连续性容易出错时，才增加更细的阶段描述。

## 运镜写法

可以直接使用标准摄影术语，例如全景、中景、特写、固定镜头、推镜、拉镜、横移、跟拍、俯拍或环绕。写清摄影机起点、运动方向、相对主体的位置和终点；不为每镜重复同一种推近或环绕。

## 特殊字符规范

需要准确旁白或对白时，使用当前工作流约定的 `{}` 标出正文，并让正文只出现一次。避免在必须准确发音的正文中使用冷僻符号、复杂公式或模型可能误读的装饰字符。画内文字优先使用常用字，并明确内容、位置和出现方式。

## 音色参考不准

- 明确说明音频只用于参考音色，不复述样本原话。
- 除音频参考外，补充少量确有帮助的音色特征，如音域、年龄感、明亮度、气息和语速。
- 当前片段的情绪表演仍在 Prompt 中单独指定，音色身份不等于平淡朗读。
- 输入模式和音频限制以实时 schema 为准，不根据素材数量猜测模式名称。

## 人物 ID 漂移

- 每个关键人物使用独立、清楚的参考，并持续使用唯一标签。
- 只连接当前片段真正需要的人物素材。
- 多视图可能制造分身或双胞胎效果；默认先用单人物单视图测试片段 1。
- 出现换脸、同款分身或服装漂移时，保留任务记录，检查素材职责与主体定义，再决定是否补侧面、背面或更干净的参考。

## 风格漂移

用文字固定媒介、材质、线条、造型、色彩和渲染体系。人物参考只负责人物身份时，不要求模型复制参考图中的背景和构图。不同镜头可以更换地点、天气、景别和主色，但人物与环境仍使用同一视觉语言。

## 视频延长 vs 分段拼接

- 同一场景的连续动作、对话和运镜可以考虑延长。
- 明显的地点、时间、叙事阶段或视觉职责变化，优先独立生成片段，再在剪辑工具中组合。
- 当前 Storytime 与 Animated Explainer 默认生成独立片段。全部片段返回后提示用户手动剪辑，以便修整局部废帧、节奏和声音边缘；只有用户明确要求时才自动拼接。

## 视频结尾有噪音

生成式视频末尾偶尔会出现极短声音毛刺或异常尾音。不要假装 Prompt 能稳定消除所有尾端问题。确保旁白长度留有余量；全部片段下载后，提示用户在剪辑工具中检查并修剪片尾约 0.1 秒附近的异常声音或画面。

## 中文发音不准

先检查人名、地名、专业词和多音字。必要时改用不改变含义的同音常用字、拆分读法或更容易发音的表达，并让用户确认文字变化。不要在未确认时擅自改变专有名词或事实。
