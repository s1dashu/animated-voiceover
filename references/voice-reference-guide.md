# 音色参考与音频转换指南

## 适用范围

本指南是音色路线选择、音色候选制作、片段 1 音色确认、纯音频剥离、后续片段音色一致性和音色资产版本管理的唯一详细来源。视频 Prompt 只声明音频的职责；平台命令与模型能力仍以实时 CLI 文档和 schema 为准。

## 选择音色路线

正式生成视频前，明确询问用户走哪条路线：

- **使用已有音色：** 先完整读取随 skill 分发的[内置音色库](reference-asset-library.md)，展示名称和声音描述，等待用户选择；宿主项目可以补充其明确登记的私有音色，但不得取代内置目录或静默指定默认音色。
- **新建音色：** 先让用户确认本期声音描述，再通过片段 1 生成新音色。

选择音色后，常规上传前只确认文件存在且文件扩展名为 `.wav`。不要例行运行 `ffprobe`，也不要在上传前检查哈希、编码、采样率、位深或声道；直接通过选定平台上传并尝试生成。平台拒绝时保留并返回实际错误，再针对该错误诊断，不提前猜测或增加预防性校验。不得扫描历史作品目录寻找同名音频作为兜底。宿主项目没有额外目录时，仍应展示 skill 内置音色与新建路线。用户未作选择时停止在生成前，不根据题材、人物或上期选择代替用户决定。

## 路线 A：使用已有音色

1. 展示 skill 内置清单以及宿主项目明确登记且状态为已确认的补充音色。选择后只确认已登记文件存在且扩展名为 `.wav`；不临时换用同名历史文件。
2. 目标平台需要远程素材时，通过该平台的正式 CLI 将标准化音频上传到本期项目或画布，并记录实际节点或素材 ID。LibTV 节点不能跨画布直接连接；跨画布时上传本地标准化文件，不借用来源画布节点。
3. 从片段 1 起，所有片段都连接同一份已选音频或同一音色 ID。Prompt 只声明它用于参考音色；当前片段的准确旁白仍只由当前 Prompt 中 `{}` 内的正文决定。
4. 先只生成片段 1；确认任务成功返回后交给用户审阅，由用户确认实际结果，通过后再生成其余片段。默认不代替用户播放、听写或执行内容质检。
5. 不从片段 1 再抽取音频替换库内参考。否则锚点会从用户选择的已登记音色悄然变成一次生成结果，失去可追踪性。

## 路线 B：通过片段 1 新建音色

1. 先确认本期声音描述。片段 1 不连接历史音频或库内音频，只在 Prompt 中写入已确认的声音描述，让音色随片段 1 一起生成。
2. 先只生成片段 1；确认任务成功返回后交给用户审阅，再次通过用户确认后才将它作为本期锚点。默认不代替用户播放、听写或执行内容质检。
3. 从最终确认的片段 1 剥离纯音频，供片段 2 以后统一使用。更换音色时从新的已确认片段重新建立锚点并创建新版本，不静默切换到其他候选音频。
4. 在 LibTV 路径中，先用 LibTV CLI 下载已确认的片段 1，再按下文转换为 WAV，最后通过 LibTV CLI 上传为独立音频节点。只为参考音色时不得直接连接完整视频：视频参考成本更高，也可能把画面、构图或动作带入后续生成。

## 独立制作音色候选

本流程只用于扩充内置或宿主项目的候选音色库，不取代“通过作品片段 1 新建本期音色”的路线。

1. 不使用 Seed Audio 或其他纯音频生成模型。通过目标平台的正式 CLI 调用 Seedance，生成一段只为分离人声而存在的视频。
2. 每个候选固定使用 `duration=5`、`resolution=480p`、`enableSound=on`；`ratio` 和模型的其余参数以实时 schema 为准并显式传入。参数只通过 CLI 传递，不写进创作 Prompt。
3. 不输入人物、图像、视频或历史音频参考，使用纯文字生成。画面只需一个与目标声音年龄和性别大致对应的简洁二维动画小人，站在干净浅色背景前面向镜头自然说话，配合轻微口型和手势，使用固定镜头。视觉仅用于让 Seedance 稳定完成视频生成，不承担音色定义职责。
4. Prompt 必须写清候选音色的年龄、性别、音域、音质、气息、语速、节奏和表达状态，并只保留与音频资产直接相关的必要约束：“全程无背景音乐且无音效，只有纯人声”。使用约 20 个汉字、语义中性且容易自然朗读的短句展示音色，不写戏剧情境，不用喊叫、耳语、哭腔或大幅情绪变化掩盖基础音色。不要为了控制无关画面添加成串的视觉负面枚举。
5. 推荐统一使用这句测试文本：`{今天阳光正好，我们一起从容地走向远方。}`。比较一组候选时保持文本完全一致，避免把台词差异误判为音色差异；5 秒内容纳不下完整台词时，优先缩短测试文本，不通过加快目标音色应有的自然语速硬塞。
6. 可直接采用以下 Prompt 结构，将方括号替换为本次候选的完整声音描述：

   > 一个简洁的二维动画[人物类型]小人站在干净的浅色背景前，面向镜头自然说话，做轻微口型和手势，固定镜头。[人物代词]使用[声音描述]。完整、准确、按原顺序说出{今天阳光正好，我们一起从容地走向远方。}全程无背景音乐且无音效，只有纯人声。

7. 下载视频后按下文剥离为 WAV。没有音轨、出现背景音乐或音效、台词错误或声音特征与目标不符时，该候选失败；保留任务 ID、节点 ID、Prompt、参数和异常记录后重新生成，不通过后期静音或降噪伪装成合格结果。动画小人的具体造型不作为音色候选的通过条件。
8. 候选通过技术检查后仍需用户确认，才可晋升为正式内置音色。Seed Audio、豆包或其他产品的音色名称只能作为声音分类和命名灵感，不代表 Seedance 会复现对应官方音色，也不得把参考名称写成未经验证的兼容声明。

## 输出为 WAV

下列转换命令输出已验证可用的 WAV。转换后只确认文件存在且扩展名为 `.wav`，随后直接上传并尝试生成：

- 容器：WAV
- 编码：16-bit little-endian PCM（`pcm_s16le`）
- 采样率：48kHz
- 声道：双声道

M4A 上传节点曾被 Seedance 拒绝；未重新验证前不要使用，也不要只修改扩展名伪装格式。

## Windows

使用 PowerShell 安装 FFmpeg：

```powershell
winget install --id Gyan.FFmpeg -e
```

重新打开 PowerShell，执行：

```powershell
ffmpeg -hide_banner -n -i ".\片段1.mp4" -map 0:a:0 -vn -c:a pcm_s16le -ar 48000 -ac 2 ".\片段1-音色参考.wav"
```

`-map 0:a:0` 要求输入文件存在第一条音轨；没有音轨时直接报错。`-n` 在目标文件已经存在时停止，避免静默覆盖。

## macOS

macOS 可以使用系统自带的 `afconvert`：

```bash
afconvert "./片段1.mp4" -o "./片段1-音色参考.wav" -f WAVE -d LEI16@48000 -c 2
```

也可以安装 FFmpeg：

```bash
brew install ffmpeg
ffmpeg -hide_banner -n -i "./片段1.mp4" -map 0:a:0 -vn -c:a pcm_s16le -ar 48000 -ac 2 "./片段1-音色参考.wav"
```

## Linux

通过当前发行版的包管理器安装 FFmpeg，再执行：

```bash
ffmpeg -hide_banner -n -i "./片段1.mp4" -map 0:a:0 -vn -c:a pcm_s16le -ar 48000 -ac 2 "./片段1-音色参考.wav"
```

## 用于后续片段

1. 已有音色路线从片段 1 起始终连接用户所选的同一份标准化音频；新建音色路线从片段 2 起连接从片段 1 建立的同一份已确认纯音频。其他平台可以使用等价的同一音色 ID。
2. Prompt 只说明“音频1仅用于参考音色”，并只补充用户已经确认且确有必要的声音特征。当前片段的准确旁白只由当前 Prompt 中 `{}` 内的正文决定，不复述样本原台词，也不借用其语义。
3. 音频承担音色参考职责时，即使只有一份参考音频，也一般选择实时 schema 支持的全能参考模式 `mixed2video`，不得仅因输入中只有音频就选择 `audio2video`；`audio2video` 不等于“单音频参考音色模式”。2026-08-01 在 Seedance 2.0 VIP（`star-video2`）实测中，纯音频 `audio2video` 任务失败并返回“参考音频不能单独使用，请添加图片或视频”，连接当前片段人物参考图与音频后使用 `mixed2video` 成功。平台若要求有效视觉输入，应连接当前片段真实需要的人物或视频参考，不为通过校验接入无关素材；正式生成前仍须重新查询 schema 和输入限制。
4. 按当前声音策略和实时 schema 设置声音参数；由 Seedance 直接生成旁白和声音时，显式保持 `enableSound=on`。
5. 上游素材、Prompt 和参数全部核对后，可以并行提交片段 2 及后续片段；生成后逐段核对实际音色、音量、语速和片尾音频。

## 资产与版本管理

- 为本期所用音色记录路线、稳定标识、用途、声音描述、来源平台及工作区／画布／节点、本地文件路径、文件哈希和确认状态。新建音色还要记录完整生成 Prompt。
- 已登记库内音色可以跨作品选择，但每次仍须由用户明确指定，并为目标画布记录新上传的节点；不得把“上期使用过”当作本期默认。
- 新建音色锚点默认只服务当前视频的后续片段，不跨作品复用，也不作为下一支视频的片段 1 输入。
- 只有用户明确确认纳入公开音色库后，才将标准化文件写入顶级 `voices/`，并在[内置音色库](reference-asset-library.md)登记稳定标识、描述、规格与哈希。不得仅因片段 1 通过本期质检就自动晋升为公开库音色。
- 用户只确认项目内复用时，音频与来源记录保留在宿主项目之外，不写入 skill。候选、失败版本、生成 Prompt、质检数据以及私有工作区、画布、节点和任务 ID 也不得写进公开资产清单。
- LibTV 同一画布内直接连接本期已确认音频节点；库内音色跨画布使用时，通过 CLI 上传标准化本地文件并登记新的节点。
- 不自行拼接 LibTV HTTP 请求，也不使用个人 API Key 重新生成已有参考。
- 修改或替换音色时创建新版本并重新确认，不覆盖原资产；除非用户明确要求，不重新生成样本或切换候选音频。
